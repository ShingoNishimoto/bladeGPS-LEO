# bladeGPS-LEO

Real-time GPS L1 C/A signal simulator for bladeRF, extended for LEO spacecraft scenarios.

This is a derivative of [bladeGPS](https://github.com/osqzss/bladeGPS) by Takuji Ebinuma
(itself based on [gps-sdr-sim](https://github.com/osqzss/gps-sdr-sim)), developed further in
[gnss_sim_receiver](https://github.com/ShingoNishimoto/gnss_sim_receiver) and made standalone here.
It depends only on libbladeRF, libm and pthread.

Main differences from the original bladeGPS:

* User motion with position and velocity at 10 Hz, in ECEF or (simple) ECI
* Visibility check for spacecraft above the ionosphere (Earth blockage with a 1000 km exclusion zone)
* Iterative signal transmission time and Earth rotation correction
* GPS transmit antenna patterns per SVN (`gnss/antenna/`), path loss and C/N0 based satellite selection
* Up to 24 channels, and a second TX channel (`-U`/`-L`) for a second receiver
* Fast mode (`-f`) that runs only the simulation and logs, without a bladeRF device
* Logs of user states (ECEF/ECI), visibility and C/N0 (`-s`)

Moon occultation and other cislunar features of gnss_sim_receiver are not included.

## Usage

```
Usage: bladegps [options]
Options:
  -e <gps_nav>     RINEX navigation file for GPS ephemerides (required)
  -y <yuma_alm>    YUMA almanac file for GPS almanacs
  -u <user_motion> User motion file (dynamic mode) for Ch1
  -U <user_motion> User motion file (dynamic mode) for Ch2
  -s <log_dir>     Log directory of user position (dynamic mode)
  -g <nmea_gga>    NMEA GGA stream (dynamic mode)
  -l <location>    Lat,Lon,Hgt (static mode) e.g. 35.274,137.014,100
  -L <location>    Lat,Lon,Hgt (static mode) of Ch2 e.g. 35.274,137.014,100
  -t <date,time>   Scenario start time YYYY/MM/DD,hh:mm:ss
  -T <date,time>   Overwrite TOC and TOE to scenario start time
  -d <duration>    Duration [sec] (max: 86400)
  -x <XB number>   Enable expansion board, e.g. '-x 200' for XB200
  -b <devstr>      bladeRF device string (standalone use, default: first device)
  -D <data_dir>    Directory of gps_table.csv and antenna/ (default: $BLADEGPS_DATA_DIR or ./gnss)
  -a <tx_gain>     TX Gain (default: -5)
  -r <azi,ele>     Rx antenna attitude in degree (default: azi=0, ele=90)
  -R <azi,ele>     Rx antenna attitude in degree of Ch2 (default: same as Ch1)
  -i               Interactive mode: North='w', South='s', East='d', West='a'
  -I               Disable ionospheric delay for spacecraft scenario
  -E               Equal distribution of rx and tx antenna pattern
  -p               Disable path loss and hold power level constant
  -j               User motion files are in ECI: angle[rad],x,y,z,vx,vy,vz (z-rotation by angle from ECEF)
  -f               Fast option, run only simulation part as fast as possible without generating IQ (no device needed).
  -v               Verbosity option
```

Example: LEO spacecraft on TX1, simulation only, with logs in `./log/`:

    $ mkdir -p log
    $ ./bladegps -t 2024/01/15,05:00:00 -e brdc0150.24n -u csv/leo_full_states_eci.csv -j -d 8000 -s ./log/ -p -E -I -f

### Scripts

The scripts in `scripts/` create a run directory `work/<date>_<name>/`, run bladegps there and
keep the logs, the command line (`command.txt`) and the console output (`bladegps.log`).
`work/` is kept in git but its contents are not. Extra arguments are passed to bladegps
(e.g. `-f` for simulation only), and the main parameters can be overridden by environment
variables (e.g. `TX_GAIN=-20 DURATION=600 scripts/leo.sh`).

| Script | Scenario |
| --- | --- |
| `scripts/static.sh` | Static ground receiver on TX1 |
| `scripts/leo.sh` | LEO spacecraft on TX1 (ECI trajectory, `-j`) |
| `scripts/leo_dual.sh` | Static ground receiver on TX1 and LEO spacecraft on TX2 |
| `scripts/realtime.sh` | Static receiver at the current time with today's ephemeris from CDDIS (`-l` required) |

### Example trajectories (`csv/`)

| File | Content |
| --- | --- |
| `leo_full_states_{ecef,eci}.csv` | LEO about 410 km, 8000 s from 2024/01/15 05:00:00, 10 Hz |
| `leo_states_{ecef,eci}.csv` | LEO about 410 km (another orbit), 8000 s from 2024/01/15 05:00:00, 10 Hz |
| `circle.csv` | Circular ground motion from the original bladeGPS (time, ECEF position) |

The LEO trajectories were generated by S2E with the simple (z-rotation only) Earth rotation;
use them with `-t 2024/01/15,05:00:00 -e brdc0150.24n`.

### User motion file

CSV without a header, one row every 0.1 s:

    c0, x, y, z, vx, vy, vz

Position in m and velocity in m/s. By default the state is ECEF and `c0` is not used.
With `-j` the state is ECI and `c0` is the rotation angle theta [rad] from ECEF to ECI.

### ECI frame

The ECI frame is rotated from ECEF about the z axis by theta only:
`r_ecef = Rz(theta) r_eci`, `v_ecef = Rz(theta) v_eci - omega x r_ecef`.
Precession, nutation and polar motion are not modeled, so it is not J2000/GCRF.
This is the frame of the `*_eci.csv` / `*_ecef.csv` trajectory pairs used with gnss_sim_receiver.

With `-s`, `user_states_eci_chN.txt` is written beside `user_states_chN.txt`. Its theta is
taken from the user motion file with `-j`, otherwise it is the IAU 1982 GMST computed from GPS time
(UT1 = UTC = GPS - 18 s). These two do not generally agree, so use `-j` when the ECI log must be
consistent with an existing ECI trajectory.

### Logs (`-s <log_dir>`)

| File | Content |
| --- | --- |
| `user_states_chN.txt` | GPS time of week, c0, ECEF position and velocity (dynamic mode) |
| `user_states_eci_chN.txt` | GPS time of week, theta, ECI position and velocity (dynamic mode) |
| `visibility_chN.txt` | Visibility of each PRN at every channel allocation |
| `cn0_chN.txt` | C/N0 of each channel (only with `-E`) |

## Build (Linux)

Install libbladeRF (e.g. from the [bladeRF](https://github.com/Nuand/bladeRF) source with
`cmake .. && make && sudo make install`), then:

    $ make          # bladegps executable
    $ make lib      # libbladegps.so, exposing bladegps_main() for embedding

libbladeRF is found with pkg-config. To use a bladeRF build tree instead:

    $ make BLADERF_CFLAGS=-I<bladeRF>/host/libraries/libbladeRF/include \
           BLADERF_LIBS="-L<bladeRF>/host/build/output -lbladeRF"

The data directory (`gnss/`) is compiled in as an absolute path (`GNSS_DATA_DIR`), and can be
changed at run time with `-D` or `$BLADEGPS_DATA_DIR`.

### Embedding

`int bladegps_main(struct bladerf *dev, int argc, char *argv[])` runs bladeGPS on an already
opened device. In that case bladeGPS uses the sample rate already set on the device and does not
close it. With `dev == NULL` (the standalone executable), bladeGPS opens the device, sets
2.6 Msps and closes it on exit.

## Docker

    $ docker build -f docker/Dockerfile -t bladegps .
    $ docker run -it --rm --privileged --device /dev/ttyUSB0 bladegps \
            /bin/bash -c "bladegps -e /opt/bladeGPS/brdc3300.18n -l 35.274,137.014,100 -d 86400"

or `cd docker && docker-compose up -d` to run it as a service.
